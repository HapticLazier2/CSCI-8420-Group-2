Interaction: administrative API requests

1. Elevation Using Impersonation  [State: Needs Investigation]  [Priority: High] 

Category:Elevation Of Privilege
Description:LAPI may be able to impersonate the context of cscli in order to gain additional privilege.
Justification:Enforce distinct service identities and least-privilege authorization. Validate caller identity and permissions for every administrative operation.

2. cscli Process Memory Tampered  [State: Needs Investigation]  [Priority: High] 

Category:Tampering
Description:If cscli is given access to memory, such as shared memory or pointers, or is given the ability to control what LAPI executes (for example, passing back a function pointer.), then cscli can tamper with LAPI. Consider if the function could work with less access to memory, such as passing data rather than pointers. Copy in data provided, and then validate it.
Justification:Avoid shared-memory access and unsafe pointer passing. Exchange validated data structures instead of executable references.

Interaction: Aminstrative API Requests

3. Potential Excessive Resource Consumption for cscli or CrowdSec DB(SQL)  [State: Needs Investigation]  [Priority: High] 

Category:Denial Of Service
Description:Does cscli or CrowdSec DB(SQL) take explicit steps to control resource consumption? Resource consumption attacks can be hard to deal with, and there are times that it makes sense to let the OS do the job. Be careful that your resource requests don't deadlock, and that they do timeout.
Justification:Apply administrative request throttling, database query timeouts, connection limits, and resource monitoring to protect cscli and CrowdSec DB(SQL) from resource exhaustion.

4. Potential SQL Injection Vulnerability for CrowdSec DB(SQL)  [State: Needs Investigation]  [Priority: High] 

Category:Tampering
Description:SQL injection is an attack in which malicious code is inserted into strings that are later passed to an instance of SQL Server for parsing and execution. Any procedure that constructs SQL statements should be reviewed for injection vulnerabilities because SQL Server will execute all syntactically valid queries that it receives. Even parameterized data can be manipulated by a skilled and determined attacker.
Justification:Use parameterized SQL queries, safe database APIs, and strict input validation. Review database access code for dynamically constructed SQL statements.

5. Spoofing of Destination Data Store CrowdSec DB(SQL)  [State: Needs Investigation]  [Priority: High] 

Category:Spoofing
Description:CrowdSec DB(SQL) may be spoofed by an attacker and this may lead to data being written to the attacker's target instead of CrowdSec DB(SQL). Consider using a standard authentication mechanism to identify the destination data store.
Justification:Authenticate the destination database endpoint and protect connection settings and credentials using secure configuration management.
